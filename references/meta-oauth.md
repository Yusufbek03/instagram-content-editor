# Официальный Instagram OAuth: настройка и границы

## Что реализовано

Локальный read-only клиент **Instagram API with Instagram Login** для Business/Creator
аккаунта: авторизация, проверка идентичности, чтение собственных публикаций, локальное
отключение. Facebook Page для этого варианта подключения не требуется.
Обычный персональный аккаунт может использовать публичный режим/свои материалы;
не обещайте ему поддержку профессионального API.

Разрешение одно: `instagram_business_basic`. Оно не означает доступ к Insights.
Эта версия сознательно использует короткоживущий токен (не более часа, с запасом
60 секунд) и требует повторного `login` после истечения. Фоновое обновление,
долгоживущие токены, Insights и hosted OAuth broker в эту реализацию не входят.

## Настройка собственной локальной установки

1. Создайте приложение в [Meta for Developers](https://developers.facebook.com/apps/).
   Добавьте Instagram и выберите **API setup with Instagram login**, не Basic Display
   и не Facebook Login. Названия пунктов панели могут меняться. Используйте Instagram
   App ID и Instagram App Secret из этой настройки, не произвольные ID других продуктов.
2. Настройте Business Login: зарегистрируйте точный HTTPS redirect URI вида
   `https://YOUR-DOMAIN/instagram/callback`. Он должен совпасть побайтно с `IG_REDIRECT_URI`,
   включая путь и отсутствие завершающего `/`. HTTP callback публично не допускается.
3. Настройте свой HTTPS reverse proxy/tunnel: только этот путь перенаправляется на
   `http://127.0.0.1:8765/instagram/callback`. Python слушает только loopback и только
   во время `login` (5 минут). Домен и TLS должны быть под вашим контролем; не используйте
   чужой callback. Отключите access/error/APM-логи URL, query strings и тел на этом маршруте:
   callback содержит одноразовый код. Tunnel-провайдер также не должен записывать запросы.
   Сам skill не устанавливает proxy, TLS и домен.
4. В Development mode добавьте и подтвердите тестовые роли согласно панели Meta.
   Для пользователей вне ролей приложения нужны разрешённый Meta уровень доступа,
   App Review/Advanced Access и проверки бизнеса, когда этого требует Meta. Настройте
   Privacy Policy и URL/процедуру удаления данных. Переключение Live само по себе
   не заменяет рассмотрение разрешений.
5. Установите Python 3.9+ и зависимости в папке навыка:

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements-oauth.txt
   ```

   Windows: используйте `.venv\Scripts\python.exe`. Нужен доступный OS vault:
   macOS Keychain, Windows Credential Manager или Linux Secret Service с открытой
   пользовательской сессией. На headless Linux без такого хранилища клиент откажет
   в подключении; хранение токена в открытом файле не используется.
6. Задайте **несекретные** настройки в своём терминале:

   ```bash
   export IG_APP_ID='YOUR_INSTAGRAM_APP_ID'
   export IG_REDIRECT_URI='https://YOUR-DOMAIN/instagram/callback'
   export IG_API_VERSION='v25.0'
   ```

   `v25.0` здесь — пример формата: выберите поддерживаемую вашим Meta app версию
   по текущей панели/документации. Версия обязательна и не переключается автоматически.
   Проверка синтаксиса в CLI не подтверждает поддержку версии платформой.
7. Лично выполните в терминале:

   ```bash
   .venv/bin/python scripts/instagram_oauth.py setup-secret
   ```

   Введите **Instagram App Secret вашего приложения** в скрытом приглашении.
   Это не пароль Instagram. Не присылайте его агенту или в чат, не помещайте в git,
   команды, URL или `.env`. CLI запишет его в системное хранилище.
8. С включённым HTTPS proxy запустите:

   ```bash
   .venv/bin/python scripts/instagram_oauth.py login '@your_username'
   .venv/bin/python scripts/instagram_oauth.py status '@your_username'
   .venv/bin/python scripts/instagram_oauth.py media '@your_username'
   ```

   Браузер открывает страницу согласия Instagram; пароль вводится только на стороне
   Instagram. `--no-browser` выводит ссылку согласия, если браузер запускаете вручную.
   Порт по умолчанию 8765; `--port` должен совпадать с upstream вашего proxy.
   Код возвращается прямо в callback, его не нужно копировать в чат или терминал.
   `connected` выдаётся только после обмена кода и успешной проверки аккаунта через API.
9. Отключение:

   ```bash
   .venv/bin/python scripts/instagram_oauth.py disconnect '@your_username'
   ```

   Команда удаляет токен выбранного аккаунта из vault, даже если он истёк. Для полного
   отзыва удалите приложение в настройках подключённых приложений Instagram. При удалении
   собственного Meta app удалите также запись `app:APP_ID` службы `instagram-content-editor`
   через системный менеджер паролей. Выгрузки/скриншоты, которые сохранял сам пользователь,
   не удаляются этой командой.

## Модель безопасности

- Нет паролей Instagram, cookies, логирования callback и передачи токена модели.
- Криптографический `state` живёт только в памяти, действует 5 минут и принимается
  однократно; проверяется даже при отказе пользователя. Неверный state не потребляет сессию.
- App Secret и токен — только в нативном vault. Plaintext/chained keyring backend запрещён.
  Vault защищает хранение на диске, но не защищает от вредоносного процесса с доступом
  к той же пользовательской сессии. Агенту не следует читать vault напрямую.
- Bearer-токен передаётся API заголовком Authorization; секрет приложения и OAuth code —
  POST-телом по HTTPS. Redirect API запрещён, чтобы не переслать заголовок другому домену.
- Локальные записи изолированы по App ID и username. После входа идентификатор пользователя
  сверяется с результатом обмена кода; неправильный аккаунт не сохраняется.
- `status`/`media` повторно проверяют идентичность. Смена username требует повторного входа.
- Ответы API выводятся только через перечень разрешённых полей; `paging.next` может содержать
  токен, поэтому не выводится и не используется. Тексты подписей остаются недоверенными данными.
- Токены короткоживущие, фоновых запросов и автоматических повторов нет. Это инструмент
  для одного владельца локального агента, не многопользовательский сервер.

## Insights: предлагаемый следующий этап, не реализован

Публичная ссылка не предоставляет охват, сохранения, удержание и демографию. Для собственной
аналитики есть два пути: предоставленная пользователем выгрузка/скриншоты либо отдельный
официальный API-доступ после согласия владельца.

Для расширения Instagram Login:

1. Проверить в текущей [документации Insights](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/insights/)
   и панели вашего Meta app разрешение для Insights, его доступность для выбранной версии
   и типа аккаунта. Не переносить имена scopes из Facebook Login в Instagram Login.
2. Запросить только базовый доступ и требуемое разрешение аналитики, только при выборе
   пользователем собственного аудита. Не добавлять публикацию, сообщения, комментарии.
   Пройти review для пользователей вне тестовых ролей. Отказ от аналитики не должен
   отключать публичный режим.
3. Добавить отдельные операции чтения user/media insights с явными периодом, timezone,
   metric/period/breakdown и перечнем поддерживаемых метрик для каждого типа медиа.
   Empty/недоступно/порог аудитории — отдельные состояния, не нули; не подменять одну
   метрику другой при ошибке API. Включить тесты отзыва scope, отсутствия данных и версий.
4. Подтвердить end-to-end тестом на собственном профессиональном аккаунте каждую
   обещанную метрику. Только после этого указывать `insights_available=true`.

## Для массовой установки «одна кнопка OAuth»

Не распространяйте общий App Secret вместе со skill. Текущий CLI требует собственного
Meta app у владельца установки. Для простого подключения внешних пользователей нужен
**отдельно размещённый OAuth broker** владельца продукта: HTTPS, пользовательские сессии,
привязанный к сессии state, шифрование токенов ключом KMS/secret manager, изоляция
пользователей, отзыв/удаление, ограничение запросов и аудит без секретов. Агент должен
получать только read-only результаты для своей сессии, а не Meta tokens. Для доставки
авторизации локальному агенту нужен одноразовый привязанный к устройству обмен;
не пересылать токены через URL. Broker не развёрнут и не входит в эту версию.

## Ошибки

| Код | Что делать |
|---|---|
| `NOT_CONFIGURED` | Проверить ID, версию, точный HTTPS callback |
| `APP_SECRET_MISSING` | Владелец app запускает setup-secret лично |
| `SECURE_STORAGE_UNAVAILABLE` / `SECURE_STORAGE_ERROR` | Установить зависимости, открыть OS vault; не использовать файл вместо него |
| `CONSENT_DENIED` | Продолжить публичный анализ, не повторять вход автоматически |
| `AUTH_TIMEOUT` / `CALLBACK_SERVER_ERROR` | Проверить порт, TLS и proxy; новый login создаст новый state |
| `ACCOUNT_MISMATCH` | Войти в указанный аккаунт; старые записи автоматически не перезаписываются |
| `REAUTH_REQUIRED` | Повторный login после истечения/отзыва |
| `PERMISSION_DENIED` | Проверить роли, review и права приложения |
| `RATE_LIMITED` | Остановить запросы и повторить позднее по решению пользователя |
| `API_ERROR` / `API_UNAVAILABLE` | Проверить доступность и конфигурацию; скрытое тело ошибки не выводится |
